# DETM Analyzer Skill

Use when: user wants to analyze a situation using the L0-L5 model, find the right operator, or determine next step.

## Core Model (embedded from DETM book)

### Codes
- `L0-L5` — analysis levels (basis to boundary)
- `S1-S5` — scene scale (person, family, society, organization, state)
- `T1-T7` — typical problem themes
- `Lx-Cn` — specific operators per level

### Basic Mapping

| Code | Short | Practical |
|------|-------|-----------|
| L0 | Existence | Resource/safety/trust/right to stop |
| L1 | Behavior | Step → effect → readout |
| L2 | Models | Stories/roles/explanations |
| L3 | Rules | Metrics/incentives/policies |
| L4 | Institutions | Power/capture/legitimacy |
| L5 | Boundaries | Mode transition limits |

### Readout Protocol
Minimal checkable signal linked to real cost. Not "estimate", but observable change.

### 5 Invariant Tests
1. Clear what we optimize and what price we accept?
2. Report linked to real readout + cost, not just number?
3. Who pays the price of the rule/metric visible?
4. Not substituted "presence" for result?
5. Predicting modes, not "character of specific person"?

---

## Quick Procedure

1. **Fix observed inputs** — what is actually visible, before interpretation
2. **Identify scene S** — scale of the system (S1..S5)
3. **Identify theme T** — problem pattern (T1..T7)
4. **Find active level** — where is the system now (L0..L5)
5. **Select operator Lx-Cn** — specific action for that level
6. **Define readout** — minimal observable signal + horizon (24h/72h)
7. **Test by invariants** — verify quality of the move

## Common Operators (quick reference)

### L0 (Basis)
- L0-C1: Stop as protection of causality
- L0-C2: Refusal to participate as lie detector
- L0-C3: Basis overexpenditure (hero mode)
- L0-C4: Frozen commitments (reduce to basis)
- L0-C5: Quarantine of rupture (isolate toxic node)
- L0-C6: Restore feedback (make truth cheap)
- L0-C7: Break link with lie (exit reporting game)

### L1 (Behavior)
- L1-C1: Minimum operation vs "do everything"
- L1-C2: Minimum readout (sensor, not "grade")
- L1-C3: Shorter cycles (more often, simpler)
- L1-C4: Stop parallelism (stop new additions)
- L1-C5: Incident analysis without punishment
- L1-C6: Recovery windows (maintenance as part of cycle)
- L1-C7: "Done" = verified (criterion of readiness)

### L2 (Models)
- L2-C1: Assigning blame instead of repair
- L2-C2: Legitimizing heroism as norm
- L2-C3: Stopping prohibited (stop = weakness/betrayal)
- L2-C4: Normalizing exit (exit as valid operator)
- L2-C5: Frame change "what counts as reality"
- L2-C6: Taboo on observation (truth banned)
- L2-C7: Explanation instead of experiment

### L3 (Rules)
- L3-C1: Metric as sensor (readout), not goal
- L3-C2: Stimulus that grows heroism
- L3-C3: Re-signing commitments to power
- L3-C4: Stop rule (limit/fuse on load growth)
- L3-C5: Return error costs to source
- L3-C6: Break reporting game (anti-imitation)
- L3-C7: Policy of axes (which projections count as reality)

### L4 (Institutions)
- L4-C1: Veto/stop right as institution
- L4-C2: Protected right to refuse and truth
- L4-C3: Institutionalization of heroism
- L4-C4: Legitimate lowering of promises
- L4-C5: Anti-capture quarantine
- L4-C6: Institution of honest feedback
- L4-C7: Institution of axis control

### L5 (Boundaries)
- L5-C1: Stop boundary (when continuation costs more than stop)
- L5-C2: Mode transition through mass refusal
- L5-C3: Heroism bifurcation (rupture vs managed decline)
- L5-C4: Power/scale boundary (commitments must drop)
- L5-C5: Cascade boundary (localize or infect)
- L5-C6: Feedback boundary (when readout stops working)
- L5-C7: Axis change (when axes must be reassembled)

## Themes (T1-T7)
- T1: Stop / pause as protection of causality
- T2: Refusal to participate / link rupture with lie
- T3: Heroic mode (resource overexpenditure vs management)
- T4: Commitment reduction to basis (freeze/cut)
- T5: Rupture quarantine (toxic node/circuit isolation)
- T6: Feedback restoration (make truth cheap)
- T7: Interpretation control (which axes count as reality)

---

## Quick Diagnostic Flow

For "fire" situation (immediate problem):
1. Take one symptom from observation
2. Map to theme T
3. Identify scene S
4. Go to L0 first — check if basis holds
5. If L0 holds → go to level with active dysfunction
6. Pick ONE operator Lx-Cn
7. Define readout with horizon (24h or 72h)
8. Verify by 5 invariant tests
