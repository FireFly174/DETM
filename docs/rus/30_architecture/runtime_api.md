# Runtime API (канон)

## Статус

Каноническая спецификация интерфейсов.

Данный документ фиксирует минимальный Runtime API для DETM,
совместимый с каноническими механизмами:

* представимость `E ∈ [0;1]` и обязательный refinement
* временные связи (links) как внешний контур
* коарсенер и глобальное время
* снапшоты как единственный интерфейс наблюдения
* инварианты как спектральные операторы

Документ описывает **контракты**, а не конкретную реализацию.

Runtime API является реализацией канонических механизмов DETM и
не вводит новых сущностей.

Все используемые понятия определены в:
- `docs/rus/20_mechanisms/level_scaling_refinement.md`
- `docs/rus/20_mechanisms/snapshots_and_state_visibility.md`
- `docs/rus/20_mechanisms/invariants_as_spectral_operators.md`
- `docs/rus/20_mechanisms/coarsener_and_global_time.md`

---

## 1. Принципы API

1. **Single-writer / multi-reader**

   * Runtime является единственным писателем живого состояния.
   * Все внешние участники читают только снапшоты.

2. **Никаких ack и барьеров**

   * API не содержит методов подтверждения обработки.

3. **События и связи — вход, снапшоты — выход**

   * Внешнее влияние поступает через публикацию событий/links.
   * Наблюдение возможно только через снапшоты.

4. **Глобальное время задаётся коарсенером**

   * Runtime продвигает базовый тик запуска дискретно (см. `docs/rus/30_architecture/global_tick.md`).

## 2. Базовые типы данных

### 2.1 RunId

Идентификатор запуска/контекста вычислений.

### 2.2 Tick

Базовый тик запуска: целое число, монотонно растёт.

Контракт:
- `base_level` определяет, тик какого уровня считается минимальным в данном запуске.
- если `base_level == L0`, то тик совпадает с `GlobalTick(L0)`.

### 2.3 LevelId

Идентификатор уровня `Ln` (например, `L0`, `L1`, ...).

### 2.4 SnapshotRef

Ссылка на снапшот состояния.

Минимальные поля:

* `run_id`
* `base_level` (минимальный уровень запуска, например `L0` или `Ln-k`)
* `tick` (номер базового тика, на котором сформирован снапшот/артефакты)
* `level`
* `digest` (хэш/дайджест)
* `uri` (ссылка на данные снапшота: in-memory / shm / file)

Опционально (рекомендуемо):
* `window_ticks` / `publish_stride_ticks` (в единицах базового тика)
* `equiv_L0_ticks` (если известно отображение в `GlobalTick(L0)`)
* `artifacts` (список ссылок на артефакты: `outerfields`, метрики, events, опциональный preview)

Схема `OuterFields` и подписок: `docs/rus/30_architecture/OuterFields_and_Subscriptions.md`.

### 2.5 Digest

Короткая проверка идентичности состояния (хэш/дайджест).

### 2.6 Event

Сообщение-намерение от внешнего узла.

Минимальные поля:

* `run_id`
* `kind`
* `due` (в единицах базового тика запуска)
* `payload`
* `causal` (опционально: зависимости)

### 2.7 LinkSpec

Описание временной связи (см. `temporary_links_and_external_channels.md`).

Минимальные поля:

* `link_id`
* `src`, `dst`
* `start_tick`, `end_tick` (или `duration_ticks`)
* `rate`
* `kernel`
* `latency` (опционально)

### 2.8 InvariantSpec

Описание инварианта как спектрального оператора.

Минимальные поля:

* `invariant_id`
* `seed`
* `params`
* `Ti` (внутреннее время)
* `level_hint` (рекомендуемый уровень)
* `signature` (дайджест/хэш оператора)

## 3. Интерфейс Runtime

### 3.1 Управление контекстом

#### create_run(config) -> RunId

Создаёт новый контекст выполнения.

Контракт:

* конфиг фиксирует базовые параметры решётки и режимы.
* runtime резервирует ресурсы (CPU/GPU) по возможности.

#### close_run(run_id) -> None

Останавливает выполнение и освобождает ресурсы.

---

### 3.2 Продвижение глобального времени

#### step(run_id, n_ticks=1) -> SnapshotRef

Продвигает глобальное время на `n_ticks` в единицах базового тика запуска.

Контракт:

* каждый тик включает:

  1. применение активных links во внешний контур
  2. шаг динамики текущего уровня
  3. проверку `E ∈ [0;1]` и обязательный refinement
  4. формирование снапшота
* возвращается `SnapshotRef` последнего сформированного снапшота.

Примечание:

* `step` может выполняться асинхронно внутри runtime-loop.
* внешние системы не должны ожидать завершения других участников.

---

### 3.3 Доступ к снапшотам (только чтение)

#### get_latest_snapshot(run_id) -> SnapshotRef

Возвращает последний опубликованный снапшот.

#### get_snapshot(run_id, tick) -> SnapshotRef | None

Возвращает снапшот конкретного тика, если он доступен.

#### read_snapshot(snapshot_ref, fields=None) -> dict

Читает данные снапшота.

Контракт:

* данные неизменяемы
* чтение не блокирует расчёт

`fields` может ограничивать выборку (например: `E`, `J`, метрики, маски).

---

### 3.4 Публикация событий

#### publish_event(run_id, event: Event) -> None

Публикует событие для будущего исполнения.

Контракт:

* runtime принимает событие и помещает в очередь.
* событие адресовано глобальному времени (`due.tick`).
* отсутствие подтверждения доставки/обработки является нормой.

#### cancel_event(run_id, event_id) -> None

Опционально: отмена события, если оно ещё не исполнено.

---

### 3.5 Управление links

#### open_link(run_id, link: LinkSpec) -> None

Создаёт временную связь.

#### close_link(run_id, link_id) -> None

Закрывает связь до истечения её TTL.

#### update_link(run_id, link_id, patch) -> None

Опционально: изменение параметров активной связи.

Контракт:

* связь влияет только через внешний контур (не прямой write в E).
* связь задана в единицах базового тика запуска.
* никакого ack.

---

### 3.6 Управление уровнями и refinement

#### set_active_level(run_id, level: LevelId) -> None

Запрос смены активного уровня детализации.

Контракт:

* уровень определяет интерпретацию тика и спектральное окно.
* смена уровня не отменяет глобальное время.
* runtime обязан сохранять канонические инварианты.

#### get_refinement_status(run_id) -> dict

Возвращает состояние активных refinement-подзадач (если есть).

Примечание:

* это диагностический интерфейс.
* он не используется для синхронизации.

---

### 3.7 Работа с инвариантами

#### load_invariant(run_id, invariant: InvariantSpec) -> None

Загружает инвариант в runtime (в память/кэш оператора).

#### unload_invariant(run_id, invariant_id) -> None

Выгружает инвариант из активного набора.

#### instantiate_invariant(run_id, invariant_id, where, when=None) -> None

Разворачивает инвариант в системе:

* `where` — регион/ячейка/уровень
* `when` — тик активации (по умолчанию текущий или ближайший)

Контракт:

* инвариант разворачивается как оператор реакции.
* если спектрального разрешения недостаточно — применяется refinement.

---

## 4. Интерфейс Coarsener (внутренний контракт)

Коарсенер может быть частью runtime или отдельным модулем,
но контракт одинаков.

### choose_level(run_id, context) -> LevelId

Выбирает уровень детализации.

### map_duration_to_ticks(level, duration) -> int

Переводит длительность (внешнюю) в глобальные тики уровня.

### advance(run_id) -> None

Продвигает глобальное время и инициирует step.

Примечание:

* коарсенер не является планировщиком задач.
* коарсенер не использует ack.

---

## 5. Интерфейс для ComfyUI

ComfyUI-ноды должны быть thin-client’ами:

* `PublishEventNode` -> `publish_event`
* `OpenLinkNode` -> `open_link`
* `CloseLinkNode` -> `close_link`
* `ReadSnapshotNode` -> `get_latest_snapshot` + `read_snapshot`
* `Viz/Analysis` -> `read_snapshot`

Комфи-граф:

* не задаёт время
* не является рантаймом
* служит интерфейсом ввода/наблюдения

---

## 6. Минимальный MVP API

Для первого рабочего контура достаточно реализовать:

1. `create_run`, `close_run`
2. `step`
3. `get_latest_snapshot`, `read_snapshot`
4. `open_link`, `close_link`
5. `publish_event`

Остальное добавляется по мере развития.

---

## 7. Инварианты API

1. Внешние участники не пишут живое состояние
2. Наблюдение только через снапшоты
3. Нет ack и барьеров
4. Все действия привязаны к глобальным тикам
5. Links действуют только через внешний контур
6. Refinement обязателен при нарушении `E ∈ [0;1]`

---

## 8. Назначение документа

Данный файл задаёт канонический интерфейс DETM Runtime.

Любая реализация (локальная, распределённая, интегрированная с ComfyUI)
считается корректной только при сохранении указанных контрактов
и инвариантов.
