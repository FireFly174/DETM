# Regime Transition Tests (DETM, RU)

Статус карточки:
- `status`: ready_for_execution
- `artifact_status`: pending transition-series artifacts
- `last_reviewed`: `2026-02-14`

Этот документ фиксирует сценарии проверки переходов между режимами.

Он дополняет baseline (`01_baseline_tests.md`) и использует существующие `exp_*` протоколы.

## T0. Stable -> Oscillatory

Идея:
- перейти из состояния с низкой активностью в устойчивый циклический режим.

Основа:
- `docs/rus/50_experiments/exp_phase_map.md`

Сигналы перехода:
- рост `J_tail` при сохранении структурной согласованности;
- появление устойчивого спектрального пика.

## T1. Oscillatory -> Turbulent/Chaotic

Идея:
- увеличить нагрузку параметров до размывания устойчивого цикла.

Основа:
- `docs/rus/50_experiments/exp_phase_map.md`
- `docs/rus/50_experiments/exp_density.md`

Сигналы перехода:
- рост вариативности метрик;
- потеря воспроизводимого доминирующего периода.

## T2. Structured -> Drift under Gradient

Идея:
- ввести слабый градиент и проверить смену режима с сохранением идентичности.

Основа:
- `docs/rus/50_experiments/exp_gradient.md`
- `docs/rus/50_experiments/exp_object_masks.md`

Сигналы перехода:
- наблюдаемый дрейф центра при контролируемой деформации формы;
- отсутствие мгновенного распада структуры.

## T3. No Channel -> Channel-Assisted Coupling

Идея:
- сравнить два режима: без канала и с каналом пониженной латентности.

Основа:
- `docs/rus/50_experiments/exp_channels.md`
- `docs/rus/50_experiments/exp_transfer_speed.md`

Сигналы перехода:
- уменьшение lag/времени согласования только в канальном режиме.

## T4. Mobility under Periodic Topology

Идея:
- подтвердить объектоподобную мобильность в torus-топологии.

Основа:
- `docs/rus/50_experiments/exp_torus.md`

Сигналы перехода:
- устойчивое перемещение без разрушения периодической структуры.

## Минимальные требования к дизайну transition-теста

1. Явно указаны `до` и `после` (режим A и режим B).
2. Задан параметр-рычаг перехода (что именно меняем).
3. Есть наблюдаемые метрики, отделяющие A от B.
4. Есть сценарий отрицательного контроля (где переход не должен происходить).

## Выходной артефакт

Для каждого `T*`:
- описание рычага перехода;
- таблица с метриками `before/after`;
- статус: `confirmed`, `not_confirmed`, `inconclusive`;
- ссылка на использованный базовый протокол (`exp_*`) и артефакты серии.
