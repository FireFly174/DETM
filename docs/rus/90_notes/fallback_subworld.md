# Fallback / subworld / pipeline swap (заметки)

Тема относится к **уровням выше L0** и/или оркестрации (ACGS). В текущем репозитории DETM она хранится как `90_notes`.
> Примечание по канону:
> В репозитории DETM канонический механизм локального уточнения/сворачивания
> зафиксирован в `docs/rus/20_mechanisms/level_scaling_refinement.md`.
> Любые идеи fallback/subworld должны быть совместимы с инвариантом представимости `E ∈ [0;1]`
> и трактовать “переполнение” (E>1) как обязательный триггер уточнения, а не как эвристику.


## 1) Зачем это нужно

Идея: на уровне `L` большая часть ячеек может быть описана **O(1)-операторами** (инвариантами/«нейронами»),
а детализация уровня `L-1` включается **только по требованию**, когда оператор перестаёт быть адекватным (выход из basin of attraction, перегрузка ёмкости).

Цель:
- держать вычислительную стоимость близкой к O(1) в устойчивых режимах;
- включать точность локально и временно, без глобальной “симуляции всего всегда”.

Аналогии (внешние):
- «внимание» в нейросетях;
- adaptive mesh refinement (AMR) в вычислительной физике;
- локальная перераспределяемая «частота обновления» через поле `τ`.

## 2) Два варианта: Patch–fallback vs pipeline swap

### Patch–fallback

1) Вырезается патч `L-1` внутри общего поля (локальная область)
2) Патч считается детальной моделью
3) Результат агрегируется обратно на уровень `L`

### Pipeline swap (subworld)

Вместо «вырезания патча в общем поле» считается, что **одна ячейка/нейрон уровня `L`** временно заменяется на вложенный мир:
- создаётся отдельная симуляция subworld уровней `L-1 … L-k` (обычно `k ≤ 3`)
- внешняя среда взаимодействует с subworld **только через границу**
- наружу возвращается агрегированный отклик

## 3) Единственный канал связи — граница

Каноническое требование: уровень `L+1` не видит внутреннюю структуру `Ω_L`, а работает с «чёрным ящиком с памятью».

Интерфейс можно мыслить так:

```mermaid
flowchart LR
  Env[Level L environment] -->|B_in (boundary stimuli)| Sub[subworld L-1..L-k]
  Sub -->|B_out (boundary response)| Env
```

Запреты:
- нельзя “передавать внутреннее состояние subworld” соседям напрямую;
- нельзя «переносить энергию вверх/вниз по уровням» как сумму амплитуд;
- допускается только управление **условиями эволюции** через граничный интерфейс.

## 4) Время: глобальный тик и асинхронные подшаги

Глобальный тик задаёт порядок причинности.
Subworld может делать несколько внутренних шагов на один глобальный тик (или эволюционировать асинхронно), но:
- наружу он публикует только сглаженный/агрегированный отклик;
- причинность не нарушается: события `L+1` не могут происходить “раньше” причин на `L`.

## 5) Критерии включения/выключения fallback

Сигналы включения:
- рост ошибки/нестабильности инвариантного описания;
- превышение «ёмкости» нейрона (выход из basin of attraction);
- конфликты фаз/периодов при взаимодействии.

Практические триггеры (прокси), которые удобно логировать:
- рост `|∇E|` (фронты/границы);
- рост `|J|` (активный перенос);
- рост `curl(J)` (циклы/вихри);
- рост локальной энтропии/неустойчивости (по выбранному прокси подавления).

Критерии возврата:
- стабилизация параметров устойчивого режима;
- возможность снова описывать поведение O(1)-оператором.
