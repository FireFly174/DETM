# Фазовая карта режимов модели

## Цель

Построить **карту режимов** (фазовую диаграмму) DETM в пространстве параметров
`kappa/alpha/beta/gamma/lambda_t`, чтобы:
- понимать, где возникают устойчивые структуры/аттракторы;
- отличать «заморозку» от «живой» динамики количественно;
- иметь базу для сравнения версий/бэкендов и для интеграции с оркестратором.

---

## Параметры и фиксированные условия

Параметры среды:
- `kappa` (проводимость),
- `alpha` (чувствительность к градиенту),
- `beta` (притяжение к `E_level`),
- `gamma` (коллективность/подавление),
- `lambda_t` (асинхронность через `τ`).

В UI/трейсах могут встречаться алиасы: `a,b,g,k,t` = `alpha,beta,gamma,kappa,lambda_t`.

Перед построением карты нужно зафиксировать (и записывать в артефакты прогона):
- размер решётки `N` и `boundary`;
- `E_level` и тип инициализации (например, «крест»/маркер/шум);
- правило влияния (если используется) и `seed`;
- длительность прогона и burn-in (сколько тиков игнорировать как разгон).

---

## Метрики режима

Рекомендуемый минимальный вектор метрик (считать по хвосту после burn-in):
- `t_stable`: время стабилизации (или `None`, если не стабилизировалось);
- `J_tail = mean(|J|)` на хвосте;
- `curl_rms(J)` (или другой устойчивый прокси «вихревости»);
- простые статистики полей: `mean/std` для `E`, `τ`, `S`;
- объектность: размер/число объектов по маске (см. `docs/rus/40_experiments/exp_object_masks.md`);
- спектральные признаки: доминирующий пик по `E_mean(t)` или по `signature(t)` (если логируете digest/signature).

---

## Классификация режимов (черновая)

Набросок практической классификации (можно улучшать по данным):

- **Заморозка**: `J_tail → 0`, форма `E` стабильна, `curl_rms` низкий.
- **Вихревой цикл / динамический аттрактор**: форма `E` стабильна, но `J_tail` и/или `curl_rms` остаются заметными.
- **Долгоживущая/хаотическая динамика**: нет стабилизации на выбранном горизонте, метрики колеблются/дрейфуют, спектр более «широкий».

Важно: границы между режимами обычно нечёткие, поэтому полезны не только метки, но и сами метрики.

---

## Протокол построения

1) Выберите 1D/2D‑срез параметров (для начала достаточно 2 параметров, остальные фиксируйте).  
2) Сформируйте сетку значений и прогоните батч (несколько `seed` на точку).  
3) Для каждого прогона:
   - сохраните конфиг/seed,
   - залогируйте компактные ряды (`E_mean(t)`, `mean(|J|)(t)`, `signature(t)`),
   - посчитайте метрики на хвосте.
4) Агрегируйте по seed:
   - среднее/квантили метрик,
   - долю «успешных» запусков (где режим устойчив и повторяем).
5) Визуализируйте:
   - теплокарты метрик по сетке,
   - кластеризацию/проекции (PCA) по вектору метрик.

---

## Замечания

- Сравнение фаз для разных `N` требует явной нормировки (см. `docs/rus/40_experiments/exp_marker_scaling.md`).
- Для воспроизводимости фиксируйте детерминизм: одинаковый seed + одинаковое влияние → одинаковая подпись/метрики.
- Если включаете внешние влияния, отделяйте «режим среды» от «ответа на сценарий» (одинаковая последовательность влияний для всей сетки).
