# Архитектурный обзор (legacy стек)

Документ фиксирует устройство старого стека `legacy/` и задаёт целевую схему модулей для ядра DETM. Описание следует канону: фокус на формальной динамике (перенос энергии, подавление/энтропия, внутреннее время) без внешних интерпретаций.

## 1. Ключевые элементы legacy/core

### Энергия, энтропия и перенос
- `Model` — базовый пошаговый апдейтер. Рассчитывает `S` как локальные квадраты превышения энергии над уровнем `E_level` с вкладом четырёх соседей, накапливает локальное время `tau = tau + v(S)`, вводит глобально-смещённый химпотенциал `mu_eff`, затем переносит энергию к правому и нижнему соседям с проводимостью `sigma = 1 / (1 + alpha * S)` и скоростью `phi = kappa * sigma * (mu_i - mu_j)`. Поле энергии клипается в `[0, 2*E_level]`.【F:legacy/core/model.py†L4-L72】
- `ModelFast` — векторизованный NumPy-аналог без Python-циклов: та же формула `S` с 8 соседями, те же `mu_eff`, `tau`, `sigma` и направленный перенос «вниз/вправо», но реализованный через `np.roll` для периодических границ.【F:legacy/core/model_fast.py†L5-L73】【F:legacy/core/model_fast.py†L75-L120】
- `ModelTorchFast` — torch-версия `ModelFast` с `conv2d` для суммы по соседям и сохранением структуры шага (без градиентов, `@torch.no_grad`). Поддерживает CPU/GPU; ожидает вызов `step()` и опциональный `sync` обёртки для зеркала в NumPy.【F:legacy/core/model_torch.py†L1-L108】【F:legacy/core/model_torch.py†L110-L174】

### Состояние
- `State` — NumPy-контейнер решётки: инициализирует поле энергии `E` с одним возмущением в центре, поля энтропии `S`, потоков `Jx/Jy`, внутреннего времени `tau` и счётчик `t_global`.【F:legacy/core/state.py†L1-L26】
- `TorchState` — аналог на torch с выбором устройства/типа и переносом на другой `device` через `to()`. Используется как источник данных для torch-модели; `mu_bar` и `t_global` остаются скалярными для совместимости с диагностикой.【F:legacy/core/state_torch.py†L1-L66】

### Runtime и диагностика
- `Engine` — цикл исполнения: повторяет физические шаги, синхронизирует зеркала (`model.sync`), обновляет диагностику, пишет поля в логгер и, при наличии визуализатора, управляет анимацией и горячими клавишами (пауза, скорость, скриншоты, новые сегменты). Поддерживает headless режим `run(max_steps)`.【F:legacy/core/engine.py†L1-L111】【F:legacy/core/engine.py†L113-L185】
- `Diagnostics` — вычисляет быструю метрику потока `A`, периодическую метрику `T` по пикам локального сигнала `P`, усреднённую энтропию `tau_mean`, энергию/энтропию объекта (`E_obj/S_obj`) на основе детекции линии, фазовые и freeze-метрики из проб по сетке, и пишет строки в `RunLogger`. Также сохраняет якоря для визуализации.【F:legacy/core/diagnostics.py†L1-L165】【F:legacy/core/diagnostics.py†L167-L246】
- `RunLogger` — сохраняет метаданные, таймсерии (CSV), истории полей `E` или набора полей, умеет бить прогон на сегменты и писать скриншоты. Истории полей складываются в `npz` при `close()`.【F:legacy/core/logger.py†L1-L156】【F:legacy/core/logger.py†L158-L261】

## 2. Ключевые элементы legacy/viz

- `Visualizer` — единственное окно Matplotlib: тепловая карта `E` (режимы `E`, `dE`, `|∇E|`), опциональные стрелки потоков `J`, scatter-якоря, гистограмма `E`, графики `T/P/A`, метрики freeze, радиальные профили A3. Поддерживает горячие клавиши (переключение режимов и quiver). Ожидает минимальный контракт от `diag` (`t_buf`, `T_buf`, `P_buf`, `A_buf`, freeze-последовательности, `last_anchors`).【F:legacy/viz/visualizer.py†L1-L124】【F:legacy/viz/visualizer.py†L126-L301】

## 3. Предлагаемая схема модулей

```
core/       – чистые модели и состояния (State/TorchState, Model*, параметры).
runtime/    – движок исполнения и диагностика (Engine, Diagnostics, RunLogger), без UI-зависимостей кроме опционального виз-хука.
viz/        – визуализация, принимающая State + Diagnostics-данные через публичные буферы/контракты.
experiments/– сценарии/CLI, связывающие сборку: выбор бэкенда, конфиг, запуск batch/viz, экспорт данных.
```

### Интерфейсы между слоями
- **Модель ⇄ Состояние**: `model.step()` мутирует `state` (E, S, Jx/Jy, tau, mu_bar, t_global); torch-реализации добавляют `sync()` для NumPy-зеркала.
- **Движок ⇄ Модель**: `Engine._step_sim(n)` вызывает `step` n раз, затем `sync` (если есть) и передаёт `state` в диагностику/логгер.
- **Диагностика ⇄ Визуализация**: диагностика экспонирует буферы (`t_buf`, `T_buf`, `P_buf`, `A_buf`, freeze-метрики, `last_anchors`) и метаданные (`E_obj/S_obj`, `mu_bar`) без прямой зависимости от Matplotlib.
- **CLI/эксперименты ⇄ Runtime**: CLI строит `State`/`Model`, включает `Diagnostics`/`RunLogger`/`Visualizer`, выбирает бэкенд (`torch`/`fast`/`slow`), конфигурирует страйды логирования и длительность прогона.

Такое разбиение оставляет ядро (перенос энергии + энтропия) чистым, позволяет менять бэкенды (NumPy/torch) без изменения визуализации и упрощает автоматизированные эксперименты/CLI.
