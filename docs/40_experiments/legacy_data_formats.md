# Legacy форматы экспорта

Анализ вспомогательных скриптов из `legacy/export_*` и `legacy/bundle_*`
показывает, что они обслуживают старый стек (`RunLogger`, `timeseries_*.csv`,
`fields_hist_*.npz`) и не совпадают с актуальным форматом экспериментов из
`experiments/`.

## `export_npz_for_analysis.py` и `export_fields_batch.py`

- **Источник**: `fields_hist_*.npz`, сохранённые `RunLogger` (поле энергии `E`,
  опционально потоки `Jx/Jy`, таймстампы `t`).
- **Что делают**: downsample по времени (`stride`), вычисляют радиальные
  усреднения вокруг центра (`E_ring`, опционально `J_ring`), усреднения/СКО по
  решётке (`mean_E`, `std_E`, `mean_Jmag`, `std_Jmag`), финальный `div`/`curl`
  потоков. По флагам пишут даунсэмплы полей `E_hist_ds`, `J*_hist_ds`.
- **Метаданные**: `center`, `r_max`, `stride`, `storage` (`float16/float32` или
  `int8_linear`), для `int8` дополнительно `*_scale/_zero` и `clip_sigma`.
- **Выход**: компактный `*.npz` с выбранными массивами; формат не фиксирован,
  состав ключей зависит от наличия потоков и флагов.

## `bundle_timeseries.py`

- **Источник**: множество `timeseries_*.csv` (колонки диагностики legacy).
- **Что делает**: для каждой таблицы оценивает количество строк, добавляет
  `run_id`, выбирает событийнo-равномерную подвыборку (`compress_timeseries`),
  гармонизирует набор колонок между прогонами, пишет партии
  `bundle_timeseries_partXX.csv` с ограничением на размер файла.
- **Метаданные**: только инференс `run_id`; структура колонок плавающая.

## `bundle_project.py`

Пакует файлы репозитория в один текстовый `project_bundle.txt` (хэш, дерево,
содержимое); не относится к данным экспериментов.

## Сопоставление с новым форматом

Новые сценарии (`marker_protocol.py`, `scaling_protocol.py`) пишут
самодостаточные артефакты:
- `metrics.csv` с инвариантами на каждом шаге (`energy_*`, `entropy_mean`,
  `internal_time_mean`, дополнительно маркерные усреднения);
- `final_state.npz` с полями `energy`, `entropy`, `internal_time` (и маской
  маркера для marker-протокола);
- `summary.json` и `catalog.json` с параметрами запуска и путями к артефактам.

## Решение по поддержке legacy-данных

Конвертер в новый формат **не добавляем**:
- старые экспортёры сохраняют радиальные/квантизованные срезы без полной
  сериализации метрик, необходимых новым экспериментам;
- набор полей плавающий и зависит от наличия потоков и параметров `stride`/`r`
  (невозможно восстановить исходные таймсерии инвариантов);
- актуальный стек перешёл на новые API и схемы данных (`metrics.csv`,
  `final_state.npz`), которые воспроизводятся пере-запусками экспериментов.

Legacy-артефакты остаются архивом для ручного анализа; при необходимости их
парсинга следует использовать оригинальные скрипты или переигрывать эксперименты
под новый формат.
