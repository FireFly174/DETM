# Диагностический бланк (24h/72h) (v2, черновик)

Назначение: быстрый рабочий шаблон, чтобы не терять причинность в цикле «симптом -> код -> шаг -> readout -> цена».

## Как заполнять (3 минуты)

1) Зафиксируй 5-10 наблюдаемых входов (факты, не объяснения).
2) Выбери сцену `S1..S5` и тему `T1..T7`.
3) Поставь первый оператор `Lx-Cn` (один шаг, не программа на неделю).
4) Задай `readout` на `24h` и `72h`.
5) Явно запиши цену/перенос цены.
6) Проверь качество хода по [printable-чек-листу тестов](#printable-tests-checklist).

## Шаблон (копируй как есть)

```text
[Контекст]
Дата/время:
Сцена: S__
Тема: T__

[Наблюдаемые входы 5-10]
1.
2.
3.
4.
5.

[Гипотеза режима]
Что, вероятно, ломается:
На каком уровне действие первым:

[Первый оператор]
Код: L_-C_
Формулировка шага (1-2 строки):
Кто делает:
Когда:

[Readout 24h]
Что должно измениться:
Как измеряем:
Что считаем "не сработало":

[Readout 72h]
Что должно стабилизироваться:
Как измеряем:
Граница stop/пересборки:

[Цена и перенос цены]
Какую цену принимаем:
Кто платит цену:
Как предотвращаем скрытый перенос цены:

[Решение по итогам цикла]
Продолжать / Скорректировать / Остановить
Следующий шаг (если есть):
```

## Мини-версия (когда совсем «пожар»)

```text
Входы: ...
S/T: ...
Первый Lx-Cn: ...
Readout 24h: ...
Цена: ...
```
